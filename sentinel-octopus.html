Setup documentation

Install Sentinel Pro

The project is designed for Kali Linux and uses Python, Go, and Rust components. Review the source repository and its license before installing.

Authorization comes first

Only install and run the tooling against systems you own or have explicit written permission to assess.

Recommended baseline

Use an isolated VM or lab network, keep snapshots, and start with status and help commands before connecting external services.

Requirements

  • Kali Linux recommended
  • Python 3.10 or newer
  • Go 1.21 or newer
  • Rust and Cargo 1.70 or newer
  • Chromium for screenshot workflows
  • OpenSSL for SentinelProxy CA generation
  • Optional API keys for external intelligence services

Before you begin

  • Create a written target scope
  • Use a dedicated lab or isolated environment
  • Review rate limits and third-party terms
  • Never place secrets in screenshots or reports

Installation

Clone the project, enter the launcher directory, run the setup script, and verify the CLI:

$ git clone https://github.com/Mrsultan7890/sentinel-pro.git
$ cd sentinel-pro/osints
$ bash setup.sh
$ sentinel --help
Clone repository

Build the Rust proxy components

$ cd sentinel_proxy/rust_core
$ cargo build --release
$ cd ../rust_fuzzer
$ cargo build --release
$ cd ../..

Build the Go services

$ cd scraper && go build -o scraper . && cd ..
$ cd dirbuster && go build -o dirbuster . && cd ..
$ cd network_mapper && go build -o network_mapper . && cd ..

Model profile

SentinelOctopus-0.5B

A compact security-oriented model fine-tuned from Qwen2.5-Coder-0.5B-Instruct for the Sentinel Pro workflow.

Model role

  • Classify security text and observed signals.
  • Turn a natural-language task into a proposed tool sequence.
  • Generate commands for operator review.
  • Draft findings, executive summaries, and remediation text.
  • Support the ReAct loop with context-aware reasoning.

Model files

The source project stores model artifacts under models/sentineloctopus-0.5b/, including weights, tokenizer files, generation configuration, chat template, and model card metadata.

BaseQwen2.5-Coder
Versionv1.1
FocusSecurity workflows
Human review is part of the design

Model-generated commands, findings, and remediation advice should be validated against the target scope, tool output, and current documentation before action.

Disclaimer and limitations

Use it responsibly and verify everything

Sentinel Octopus is a powerful research and security automation project. Capability does not imply permission, accuracy, or safety in every environment.

Legal boundary

Use only for authorized security testing, defensive research, education, and OSINT work. Obtain written permission before scanning, probing, or collecting data about any third-party system or person.

Experimental behavior

Autonomous planning, machine-learning classifications, and generated commands can be incomplete or incorrect. Treat every output as a hypothesis until independently verified.

Environment dependence

Results depend on installed tools, network access, API credentials, target configuration, rate limits, and the versions of Python, Go, Rust, and model dependencies.

Privacy and data handling

OSINT and breach workflows may process sensitive personal data. Minimize collection, protect local databases, redact secrets, and follow applicable privacy and retention requirements.

Depending on the modules you use, configuration may include Groq, Telegram, Shodan, NVD, VirusTotal, Have I Been Pwned, Dehashed, IntelX, LeakCheck, SecurityTrails, Censys, URLScan, BuiltWith, GreyNoise, PhishTank, GitHub, and Tor. Never paste credentials into a report, screenshot, terminal history, or public issue.

SentinelProxy v2

Local proxy workflow

SentinelProxy provides a local interception and analysis interface. Configure only approved browsers and targets, and keep the generated CA certificate private.

Proxy endpoint

The documented local endpoint is 127.0.0.1:8082. Import the generated Sentinel CA only into a dedicated lab browser profile.

Start the proxy

$ cd sentinel_proxy
$ python3 main.py

# Or from the main CLI:
$ sentinel-pro> proxy start
Reporting

Turn observations into a reviewable record

Reports should include scope, methodology, evidence, severity rationale, remediation, and clear separation between observed facts and model-generated interpretation.

JSON

Machine-readable findings, target context, severity, evidence hashes, and MITRE ATT&CK mappings.

HTML and PDF

Human-readable reports with severity colors, charts, evidence sections, timestamps, and signatures.

Action report

Per-finding guidance covering what happened, how to reproduce it safely, how to fix it, and useful references.

Safe operating checklist

Before pressing enter

A short checklist for labs, bug bounty programs, and professional engagements.

Confirm

  • Written authorization and target list
  • Testing window and rate limits
  • Approved tools and data sources
  • Backup, rollback, and stop conditions
  • Private storage for credentials and evidence

Avoid

  • Testing outside the approved scope
  • Running destructive actions without approval
  • Sharing personal data or secrets
  • Trusting generated commands without review
  • Leaving monitoring services running unintentionally
